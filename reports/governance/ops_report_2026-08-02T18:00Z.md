### New this run — `Automerge tier policy` is the dominant source of false red

Reds concentrate on two gates: `AgentOps packet scope` (4x: #904, #1086, #1111,
#1145) and `Automerge tier policy` (4x: #1118, #1149, #1151, #1153) — eight of
the eleven red PRs. But the more consequential number is the *cancelled* one:

- Across the 41 open PRs there are **85** `Automerge tier policy` attempts, of
  which **26 (30.6%) concluded `CANCELLED`**.
- **12 of 41 open PRs (29%) are green only after dedup**, and in **every one of
  the twelve** the sole superseded bad attempt is `Automerge tier policy`:
  #1067, #1084, #1085, #1173, #1181, #1182, #1183, #1184, #1185, #1188, #1189,
  #1202.
- Mechanism, in the workflow itself: `concurrency: group:
  tier-policy-${{ github.event.pull_request.number }}` with
  `cancel-in-progress: true` (`.github/workflows/automerge-tier-policy.yml:40-42`),
  fired by **8** `pull_request` types including `edited` — which triggers on title
  *or body* changes (`:27`) — plus **3** `pull_request_review` types (`:33`). Any
  retitle, body edit, label change, or review event during an in-flight attempt
  kills it and leaves a permanent `CANCELLED` CheckRun at the required check's
  name.
- Worst case observed: **#1189 burned 5 consecutive `CANCELLED` attempts in 13
  minutes** (08:46:16Z → 08:58:25Z) before succeeding at 08:59:53Z.

**What this does and does not break.** It does *not* break branch protection:
#1173, #1181 and #1184 each carry a `CANCELLED` attempt and are nonetheless
`CLEAN`, which confirms GitHub evaluates only the latest run per check name. The
damage is to **observers** — `gh pr checks`, dashboards, and any naive rollup
consumer sees a red required check on 29% of the open queue. That is precisely
the artifact this lane's dedup step exists to remove, and it is now large enough
to be the single biggest distortion in the PR picture.

Cheap fix worth an operator ruling: narrow the `types:` list (dropping `edited`
alone would remove the body/title-edit class of cancellations) or scope
`concurrency` to the head SHA rather than the PR number so that non-code events
do not cancel a still-valid attempt.

Caveat on causality: this lane edits #1173's body on every run, and #1173's
`CANCELLED` attempt started 2026-08-02T12:09:14Z — inside the 12:00Z run's
window, superseded by a `SUCCESS` at 12:10:47Z. That is suggestive of
self-inflicted cancellation but **not proven**; #1151 shows a `CANCELLED` at
12:09:23Z, nine seconds later, and this lane did not edit #1151's body. The
cheapest test is to read the `edited`/`synchronize` event timestamps on both PRs'
timelines and compare against the cancelled attempts' `startedAt`.
