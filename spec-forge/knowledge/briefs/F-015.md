# F-015 — verify:all chained gate (s0-verifiers, deps: F-001,F-002,F-011,F-012,F-013,F-014)

## What it really requires
- One command chaining the six EXISTING gates, each result printed: typecheck (package.json:16), bun test (package.json:11), boot smoke (`bash scripts/boot_smoke.sh`, F-002), ratchet (`bash scripts/ratchet.sh`, F-008..F-012), lint (package.json:15, carries `--max-warnings 19` budget from eslint.config.js:4-11), format:check (F-014).
- "Each sub-gate's result printed" rules out a bare `&&` chain in package.json — a small `scripts/verify_all.sh` with per-gate PASS/FAIL echo lines and fail-fast exit is the clean shape; `"verify:all": "bash scripts/verify_all.sh"`.
- Call the canonical scripts; do not re-implement any check inline. This becomes the per-commit gate for every later feature, so total runtime matters: typecheck ~s, suite ~30s, boot smoke ≤20s poll (boot_smoke.sh:14), ratchet <1s.

## The non-obvious pitfall
A green run can MUTATE the tree: ratchet auto-tightens — any improved counter rewrites the tracked scripts/ratchet_baselines.txt at end of a fully green run (ratchet.sh:174-183, LESSONS.md:25). verify:all exiting 0 while leaving an unstaged tracked-file diff will then break the clean-state/docops gates at commit. Either have verify_all.sh warn loudly when `git status --porcelain` changed across the run, or document that a tightened baselines file must ride the commit. Also: every prompt-pack script here must run under bash, never zsh (`set -- $size` word-split failure, claude-progress.txt:7-11), and must not contain the literal recursive-force-rm string anywhere (fourfold-shakti-warrant scans staged text — LESSONS.md:10,13).

## Fastest verification
`bun run verify:all` exit 0 twice with six result lines. Negative probe: append a failing `expect` to one test file (or break one gate), observe nonzero exit + the failing gate named, restore via `git show HEAD:<path> > <path>`. Confirm no tracked churn after a green run.

## What NOT to do
Don't add new checks (goldens are F-018's gate, not part of this chain per the feature text). Don't parallelize gates. Don't swallow sub-gate exit codes with `|| true` or unguarded pipelines — each gate's failure must propagate to the chain's exit code.
