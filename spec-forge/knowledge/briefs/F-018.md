# F-018 — golden-diff checker (s0-verifiers, deps: F-016, F-017)

## What it really requires
- `scripts/golden_diff.sh`: capture fresh frames into a mktemp dir via `GOLDEN_OUT_DIR=$(mktemp -d) bash scripts/golden_capture.sh` (the override F-016 was told to build), then `diff -ru` against the committed tests/golden/; exit 0 clean, exit 1 NAMING the first drifted frame path.
- Bake the approval doctrine into the failure message: "approved drift = re-capture and commit via golden_capture.sh; never edit a golden in place" (CONSTITUTION.md:173-176).

## The non-obvious pitfall
The checker must leave zero worktree churn. If it captures into tests/golden/ directly, every run dirties tracked files and the clean-state law (CONSTITUTION.md:144, "Untracked junk = not clean") plus each feature's `git status --porcelain` gate goes red. Capture to temp, compare, clean up — and clean the temp dir with `find "$d" -mindepth 1 -delete; rmdir "$d"` (boot_smoke.sh:17-21 pattern), never the literal recursive-force-rm string, which fourfold-shakti-warrant blocks even inside scripts (LESSONS.md:10).

## Fastest verification
1. Unchanged tree → exit 0. 2. Negative probe: change one visible label (a tab title in mockContent.ts:7-118 is the cheapest single-line visual change) → exit 1 naming the drifted frames → revert via `git show HEAD:src/mockContent.ts > src/mockContent.ts` (claude-progress.txt:90) → exit 0 again. 3. `git status --porcelain` identical before/after both runs.

## What NOT to do
Don't add golden_diff to verify:all (F-015's chain content is fixed by its feature text; wiring goldens into the per-commit chain is a separate decision). Don't implement approval flags/allowlists — drift is binary here. Don't compare SGR escapes; text frames only. Don't "helpfully" re-capture on failure — the checker only reports.
