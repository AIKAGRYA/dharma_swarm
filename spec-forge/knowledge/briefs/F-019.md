# F-019 — truecolor preflight gate (s0-verifiers, deps: F-002)

## What it really requires
- `scripts/truecolor_preflight.sh` asserting three links of the chain, each with its own diagnostic on failure: (1) COLORTERM=truecolor reaches the app environment — the run env injects it per pane command (boot_smoke.sh:30), so check inside a launched pane, not the host shell; (2) tmux RGB terminal-features are on (`tmux display -p '#{client_termfeatures}'` contains RGB, or equivalent server-option check); (3) a literal `38;2` SGR sequence survives the pipeline — printf a probe like `\033[38;2;255;158;59mTRUECOLOR-PROBE\033[39m` inside a pane and `tmux capture-pane -e` it back. This exact method already worked at S0-INIT; evidence format at spec-forge/truecolor-preflight.txt:1-3.

## The non-obvious pitfall
The app itself emits ZERO 38;2 sequences today: theme.ts:1-14 maps all 12 tokens to named ANSI-16 colors, and the pre-theme SGR goldens were explicitly recorded as 16-color-only (claude-progress.txt:12). A preflight that asserts 38;2 in an APP frame fails until S4 lands — the 38;2 evidence MUST come from a synthetic printf probe routed through tmux, which is precisely what proves the terminal chain won't quantize S4's colors when they arrive.

## Fastest verification
Run in the build tmux env → exit 0, stdout evidence contains literal `38;2` (grep -F '38;2'). Negative: launch the probe pane with COLORTERM stripped from the pane command → exit 1 with a diagnostic naming the missing link. Run twice for stability. Bash, never zsh (claude-progress.txt:7-11); temp/session cleanup per boot_smoke.sh:17-21 (no recursive-force-rm literal — LESSONS.md:10).

## What NOT to do
Don't mutate tmux server options to force the check green — the gate exists to FAIL when the environment is wrong (its whole point: overnight aesthetic grading must never judge quantized colors, CONSTITUTION.md:316-318). Don't overwrite spec-forge/truecolor-preflight.txt (that's S0's receipt). Don't gate on $TERM string equality or terminal emulator names.
