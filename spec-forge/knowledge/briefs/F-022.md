# F-022 — compactShell ≤90 regression test (s4-theme, deps: F-021)

## What it really requires
- A bun test that renders App at width ≤ 90 and asserts compact-layout markers, plus an 80x24 tmux capture showing the compact shell. Cheap, durable markers: header brand renders "DHARMA" not "DHARMA TERMINAL" (ShellHeader.tsx:30) and statusLabel "OFF" not "OFFLINE" (ShellHeader.tsx:24-25); active tab renders bracketed `[Chat]` (TabBar.tsx:31).
- THE width mechanism: App does NOT read the ink test stdout. It computes `terminalWidth = (process.stdout.columns ?? Number(process.env.COLUMNS ?? "0")) || 120` (app.tsx:2444-2446). The TestStdout `columns = 220` in tests/app.test.ts:474 never reaches it. Under bun test, process.stdout is piped so `.columns` is undefined → the `COLUMNS` env var is the lever: set `process.env.COLUMNS = "80"` before render, restore in a finally/afterEach. (Mind the `??`: if .columns is ever defined, env is ignored — assert the precondition or stub `process.stdout.columns` explicitly.)

## The non-obvious pitfall
app.test.ts is the 442KB shared choke (CONSTITUTION.md §8.5) and nearly every App feature edits it — but nothing in the suite covers compactShell at app level today (grep "compact" in tests/ hits only component/preview tests). Prefer a small dedicated test file (the suite already has 13 separate files; bunfig.toml preload applies to all) or a clean append at the end of app.test.ts — never leave the megafile half-edited at commit. Remember the sandbox preload re-applies state-dir env every beforeEach (tests/setup.ts:16-22); your COLUMNS save/restore must not fight it.
