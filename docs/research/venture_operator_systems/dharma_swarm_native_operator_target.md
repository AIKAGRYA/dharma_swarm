# Dharma Swarm Native VentureCell Operator Target

**Date:** 2026-05-27  
**Status:** Target architecture sketch derived from Cofounder/Polsia observation  
**Primary live test:** Darshan Season 0  

---

## North Star

Dharma Swarm should eventually contain its own version of Cofounder/Polsia: a native interface for creating, operating, observing, funding, and learning from many VentureCells.

This should not be a clone of any external product. It should be the interface through which the octopus knows and moves its tentacles.

## Why Cofounder Is Useful Now

Cofounder is teaching the operating-shell side:

- how a user is onboarded into a company plan;
- how agent roles are presented;
- how brand/design work is sequenced;
- how tasks and approvals are represented;
- how publish/review flows work;
- how managed services reduce founder burden;
- how marketing, sales, design, and engineering agents are separated;
- how a project can graduate to owner-controlled infrastructure.

Darshan should use this while keeping Dharma Swarm as the deeper source of truth.

## Why Polsia Still Matters

Polsia is teaching the ambition side:

- one person can attempt to operate company-scale workflows through agents;
- the platform can position itself as "AI runs your company";
- revenue-share incentives create both alignment and capture risk;
- high autonomy creates a need for better receipts, customer-revenue attribution, and operator trust.

Polsia should be studied, not trusted with Darshan's first public surface.

## Native Operator Requirements

A Dharma Swarm-native operator must support:

### VentureCell Creation

- name;
- beneficiary/customer;
- value proposition;
- organ/domain parent;
- first proof;
- 30/90-day target;
- self-funding hypothesis;
- kill condition;
- spinout condition;
- allowed autonomy;
- forbidden autonomy;
- operator roster;
- budget;
- telos constraints.

### Work Operation

- task board;
- agent routing;
- role scopes;
- review states;
- approval gates;
- calendar;
- launch checklist;
- weekly review;
- runbook generation;
- artifact/library storage.

### Trust And Receipts

- every operator action logged;
- every public artifact traceable to a source of truth;
- claim ledger / source pack / counterframe / attention ledger where relevant;
- human approval before external action;
- correction/refusal path;
- reversible state transitions.

### Learning Loop

- Chetana ingest;
- ontology object creation;
- TaskBoard follow-up;
- DecisionLog record;
- source-map updates;
- reader/client feedback ingest;
- next-action routing;
- cross-cell signal propagation.

### Growth And Revenue

- outreach tracker;
- reader list;
- paid membership tracker;
- donation/preorder tracker;
- institutional lead tracker;
- advisory pipeline;
- sponsor compatibility screen;
- channel analytics;
- derivative distribution ledger.

## Operator Boundary Rule

External operators can operate shell work. Dharma Swarm owns judgment.

Native operators must preserve this rule internally too:

- agents may draft;
- agents may route;
- agents may package;
- agents may measure;
- agents may recommend;
- but final claims, public commitments, sensitive publishing, source trust, and kill/spinout decisions remain gated.

## Darshan As The First Test

Darshan is the right test because it forces both sides:

- public artifact quality;
- reader acquisition;
- distribution and revenue;
- memory/ontology/task/decision materialization;
- evidence discipline;
- attention ethic;
- external operator collaboration;
- future native-operator requirements.

If Darshan only becomes a publication, the operator target failed.

If Darshan only becomes internal substrate proof, the public product failed.

The native operator target is proven when one strong Darshan artifact becomes:

```text
canonical artifact
-> source pack
-> claim ledger
-> distribution swarm
-> reader feedback
-> revenue/advisory signal
-> Chetana memory
-> ontology links
-> TaskBoard follow-up
-> DecisionLog delta
-> next VentureCell action
```

## Immediate Build Implications

1. Track every Cofounder interaction in the generic external operator log.
2. Keep the Polsia log as a legacy/comparison surface.
3. Add a distribution ledger before scaling derivative posts.
4. Export any Cofounder tasks/artifacts manually into Dharma Swarm until a connector exists.
5. Treat Cofounder outputs as suggestions until validated against Darshan gates.
6. Use Cofounder aggressively for shell execution, not for final seeing.
