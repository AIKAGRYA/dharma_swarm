## 0. One-Sentence Summary

Drive named runtime surfaces from **31.25% joined / 56.25% joined-or-adapter-ready** to **100% classified-and-enforced** by (a) closing the RuntimeStateStore legacy bypass with a CI gate, (b) wiring adapters into 5 missing boundaries, (c) recording mapping receipts for 5 parallel ID lineages — all with shadow-run + strangler-fig discipline.

---

## 1. Goals

**G1. Eliminate the legacy ledger lie.**
After this phase, **no row in `task_claims`, `delegation_runs`, or `artifact_records` exists without a matching row in `execution_identities`** on any canonical code path. The legacy sync helpers either require identity or are explicitly quarantined behind a `legacy_no_identity_allowed` flag tested-and-named.

**G2. Saturate boundary tollbooths.**
Five currently-missing boundaries (TaskBoard create, MessageBus consume, MessageBus send, ToolRegistry dispatch, RuntimeArtifactStore writes) become **adapter-ready** with `require_identity=False` default and **fail-closed when toggled true**. Each gains tests proving missing identity raises `MissingExecutionIdentity`.

**G3. Make parallel ID lineages queryable.**
Five mapping receipts are recorded by the ledger:
- `workflow_started` / `workflow_checkpointed` (workflow_id → run_id)
- `proposal_created` (proposal_id → run_id)
- `event_emitted` / `event_consumed` (event_id → run_id)
- `ontology_action_requested` / `ontology_action_applied` (creating `ontology_action_id`, mapping to run_id) — **note: this overlaps with the queued C2 ontology phase; only the mapping receipt lands here, not the enforcement of `ActionDef.modifies`**
- `engine_artifact_recorded` (engine artifact_id → run_id)

**G4. Add CI gates that prevent regression.**
Two new test layers:
- **Ledger invariant test:** for every `run_id` in `delegation_runs` after a canonical-path test fixture, assert the matching `execution_identities` row exists.
- **Surface adoption test:** for each newly-wired boundary, a test in `require_identity=True` mode proves missing identity fails.

**G5. Publish a deterministic adoption metric.**
A test or script computes "% surfaces joined / adapter-ready / missing / quarantine" and writes it to `reports/governance/spine_adoption_metric.json`. Goal: tracked over time, target ≥95% joined-or-adapter-ready by end of phase.

---

## 2. Non-Goals

**NG1. Not implementing C2 ontology enforcement.** `ActionDef.modifies` and `requires_approval` becoming **enforced** runtime contracts is the next phase. This phase only adds the `ontology_action_id` mapping receipt — the action ID identifier itself — so the next phase has a join key to use.

**NG2. Not unifying the workflow engine with the spine.** `workflow.py`, `workflow_graph.py`, `durable_execution.py` keep their `workflow_id` semantics. We only add a **mapping receipt** that joins `workflow_id` to `run_id`. We do not refactor the workflow system.

**NG3. Not migrating to Temporal/DBOS/Restate.** dharma_swarm's runtime spine is a custom build on SQLite. This phase improves operational discipline of the existing spine. A future "should we adopt Temporal?" decision is **out of scope here**.

**NG4. Not adding new agents.** No new fleet members during this phase. The fleet is frozen at claude + devin + hermes + mike + perplexity until saturation hits target.

**NG5. Not amending doctrine.** Doctrine is converged ("kill nothing — metabolize", co-equal contributors, runtime truth spine). This phase is implementation work under doctrine, not doctrine work.

**NG6. Not removing legacy sync helpers.** Strangler-fig: legacy helpers stay alive behind the façade until **every caller migrates**. Removal is the slice after the migration completes.

## 4. Slice Plan

### Slice A — Close the Legacy Ledger Bypass + Add CI Gate

**Files touched:**
- `dharma_swarm/runtime_state.py` (legacy sync helpers)
- `dharma_swarm/opportunity_dispatcher.py` (caller)
- `tests/test_runtime_state.py` (existing)
- `tests/test_runtime_state_invariants.py` (new)
- `tests/test_opportunity_dispatcher_identity.py` (new)

**Implementation:**
1. Add optional `identity: ExecutionIdentity | None` and `legacy_no_identity_allowed: bool = False` parameters to `create_task_claim_sync` (`runtime_state.py:1595`) and `create_delegation_run_sync` (`runtime_state.py:1686`).
2. When `identity` provided: write `execution_identities` row **before** claim/run row in a single SQLite transaction. Write `runtime_receipt(receipt_type="legacy_sync_identity_attached")`.
3. When `identity` is None and `legacy_no_identity_allowed=False`: raise `MissingExecutionIdentity`.
4. When `identity` is None and `legacy_no_identity_allowed=True`: write claim/run row, also write `runtime_receipt(receipt_type="legacy_sync_no_identity", status="quarantine")` so the bypass is auditable.
5. Update `OpportunityDispatcher` to construct one `ExecutionIdentity` per opportunity dispatch and pass it through. Tag the legacy callsite explicitly.
6. Write invariant test: spin up a `RuntimeStateStore`, run a canonical fixture, assert `SELECT COUNT(*) FROM delegation_runs WHERE run_id NOT IN (SELECT run_id FROM execution_identities)` returns 0.

**Success criteria (Slice A):**
- No new canonical `run_id` can exist without a matching `execution_identities` row.
- `OpportunityDispatcher` runs are queryable via `get_run_ledger(run_id)`.
- Legacy bypass is named, quarantined, and emits a quarantine receipt.

**External grounding:** Strangler-fig façade ([Azure Architecture Center](https://learn.microsoft.com/en-us/azure/architecture/patterns/strangler-fig)). The legacy helpers remain alive as a façade-routed code path with explicit quarantine flag. Migration is incremental — callers move one at a time.

### Slice B — Adapter Saturation on 5 Missing Boundaries

**Files touched:**
- `dharma_swarm/spine/adapters.py` (already exists, broadly invoke it)
- `dharma_swarm/task_board.py` (create/create_batch)
- `dharma_swarm/message_bus.py` (send + consume_events)
- `dharma_swarm/tool_registry.py` (dispatch)
- `dharma_swarm/artifact_store.py` (RuntimeArtifactStore.create_text_artifact)
- `dharma_swarm/engine/artifacts.py` (mapping-only, not refactor)
- `tests/test_runtime_truth_spine_adoption.py` (new)

**Implementation pattern (each boundary):**
1. Import `adapt_execution_identity`, `attach_execution_identity`, `runtime_receipt_kwargs` from `dharma_swarm.spine.adapters`.
2. At the entry of the boundary function, call `adapt_execution_identity(carrier, surface="<surface_name>", require_existing=self._require_identity)` to extract-or-construct identity.
3. Before any side effect, call `try_begin_idempotent_side_effect_sync(idempotency_key=identity.idempotency_key, side_effect_key="<surface>_<op>")`.
4. After side effect, call `complete_idempotent_side_effect`.
5. Write a runtime receipt with `runtime_receipt_kwargs(identity, receipt_type="<surface>_<op>", status="completed")`.
6. Add a constructor param `require_identity: bool = False` and an instance flag.

**Per-boundary specifics:**

- **TaskBoard.create / create_batch:** generate identity from task metadata; persist full identity in task row (not just trace_id at `task_board.py:212`); emit `task_created` receipt.
- **MessageBus.send (raw):** require identity; emit `message_sent` receipt.
- **MessageBus.consume_events:** receiver-side `try_begin_idempotent_side_effect` per (event_id, handler) tuple; emit `message_consumed` receipt. **This is the Kafka idempotent-consumer pattern** ([lydtechconsulting.com](https://www.lydtechconsulting.com/blog/kafka-idempotent-consumer-transactional-outbox)).
- **ToolRegistry.dispatch:** require identity; emit `side_effect_intent` before handler, `side_effect_complete` after; mandatory idempotency.
- **RuntimeArtifactStore.create_text_artifact:** make `run_id` and `trace_id` mandatory (currently optional at `artifact_store.py:40`).
- **engine/artifacts.py:** **do not refactor**. Add a mapping receipt: `RuntimeStateStore.record_engine_artifact_mapping(engine_artifact_id, run_id, trace_id)` callable optionally from `engine/artifacts.py:create_artifact`.

**Success criteria (Slice B):**
- 5 boundaries gain `require_identity` toggle defaulting false.
- 5 tests prove `require_identity=True` mode raises on missing identity.
- 5 tests prove duplicate idempotency does not repeat side effects.
- Engine artifact mapping receipt is callable (not yet required).

**External grounding:** Idempotent consumer pattern ([Kafka idempotent consumer + transactional outbox, Lydtech, 2025](https://www.lydtechconsulting.com/blog/kafka-idempotent-consumer-transactional-outbox)). DBOS's `try_begin_idempotent_side_effect` pattern matches DBOS workflow-id-as-idempotency-key ([docs.dbos.dev](https://docs.dbos.dev/tutorials/idempotency-tutorial)).

### Slice C — Mapping Receipts for Parallel Lineages

**Files touched:**
- `dharma_swarm/runtime_state.py` (add 5 receipt types and helper methods)
- `dharma_swarm/workflow.py` + `workflow_graph.py` + `durable_execution.py` (call mapping)
- `dharma_swarm/message_bus.py` (event mapping at emit + consume)
- `dharma_swarm/evolution.py` + `dharma_swarm/sealed_packet_apply.py` (proposal mapping)
- `dharma_swarm/ontology.py` (action_id generation + mapping — **mapping only, not enforcement**)
- `dharma_swarm/engine/artifacts.py` (artifact mapping)
- `tests/test_spine_mapping_receipts.py` (new)

**Implementation:**
1. **Add new receipt types:** `workflow_started`, `workflow_checkpointed`, `proposal_created`, `event_emitted`, `event_consumed`, `ontology_action_requested`, `engine_artifact_recorded`.
2. **Workflow mapping:** when `CompiledWorkflow.__init__` runs (`workflow.py:231`), if `runtime_state` is in scope, write `workflow_started(workflow_id, run_id, trace_id)`. Same for `WorkflowGraph.execute` (`workflow_graph.py:240`).
3. **Proposal mapping:** when a self-mod proposal is created (broad set in `evolution.py`), write `proposal_created(proposal_id, run_id, trace_id)`.
4. **Event mapping:** when `MessageBus.emit_event` succeeds, write `event_emitted(event_id, run_id, trace_id)`. When `consume_events` finishes, write `event_consumed(event_id, run_id, handler_id)`.
5. **Ontology mapping:** **generate `ontology_action_id` in `OntologyRegistry.execute_action` (`ontology.py:763`)** — UUID4 — and write `ontology_action_requested(ontology_action_id, run_id, action_name, object_type, object_id)` **before** the action mutation, `ontology_action_applied(ontology_action_id, status)` **after**. **Do NOT enforce `ActionDef.modifies` here — that's the next phase.**
6. **Engine artifact mapping:** `engine/artifacts.py:create_artifact` accepts optional `(run_id, trace_id)`; if provided, calls `runtime_state.record_engine_artifact_mapping(engine_artifact_id, run_id, trace_id)`.
7. **Query helpers:** add `RuntimeStateStore.get_runs_by_workflow_id`, `get_runs_by_proposal_id`, `get_runs_by_ontology_action_id`, `get_runs_by_event_id`, `get_runs_by_engine_artifact_id`.

**Success criteria (Slice C):**
- 5 mapping receipt types exist with helper methods.
- 5 query helpers exist and return correct results in tests.
- `get_run_ledger(run_id)` includes mapped foreign IDs in output.

**External grounding:** Temporal's WorkflowId + RunId tuple is queryable as one unit from event history ([docs.temporal.io](https://docs.temporal.io/workflow-execution/workflowid-runid)). Palantir's Action Log creates one log object per Action submission, FK-linked to every edited object ([palantir.com](https://palantir.com/docs/foundry/action-types/action-log/)). Mapping receipts give dharma_swarm an equivalent queryable ledger surface.

## 6. Risk Register

| # | Risk | Likelihood | Mitigation |
|---|------|------------|------------|
| R1 | Slice A breaks `OpportunityDispatcher` callers that depend on legacy behavior | High | Keep legacy path alive behind `legacy_no_identity_allowed=True` flag; migrate callers one at a time (strangler-fig) |
| R2 | Slice B's mandatory idempotency on ToolRegistry breaks existing tool calls that have no idempotency_key | High | `require_identity=False` default; idempotency only enforced when toggle flipped per-tool |
| R3 | Slice C's mapping receipts cause performance regression at high event volume | Medium | Mapping receipts are **append-only** rows; SQLite handles this well; add index on (foreign_id, run_id) |
| R4 | Confusion with queued C2 ontology phase | Medium | Mapping receipt for `ontology_action_id` lands here; enforcement of `ActionDef.modifies` lands next phase; PR descriptions name the split explicitly |
| R5 | Process restart between `try_begin` and `complete_idempotent_side_effect` leaves orphan rows | Medium | Add recovery routine: on startup, scan `idempotency_records` for `status="started"` rows older than 5 min and mark `status="orphaned"`; do not retry automatically |
| R6 | New CI invariant test makes existing PRs fail | High | Land the test in a **separate PR** first with `xfail` markers on known-failing fixtures; remove `xfail` as Slice A migrates callers |
| R7 | Workflow versioning gap remains unaddressed | High (deferred risk) | Explicitly noted in NG3; queue "workflow versioning phase" as a follow-up; reference Restate immutable deployments + Temporal worker versioning |
| R8 | Devin's runaway loop reactivates and floods the bus mid-phase | Medium | Devin-quarantine still in place from earlier sessions; perplexity fleet broadcast is the trip wire; human operator decides re-enable |
