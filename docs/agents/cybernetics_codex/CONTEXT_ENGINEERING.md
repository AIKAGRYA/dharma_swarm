# CONTEXT ENGINEERING DESK - cybernetics_codex

This desk defines the minimum context bundle for cybernetic loop work.

## Required Inputs

- The original 13-loop campaign prompt or its latest faithful restatement.
- `CYBERNETIC_LOOP_MAP.md`
- `docs/ops/CYBERNETICS_CODEX.md`
- `docs/governance/ACTIVE_TRACK.yaml`
- `ACTIVE_SURFACE_MANIFEST.yaml`
- `docs/state/BROKEN_REGISTER.md`
- runtime DB summary from `cybernetics_codex_audit.py`
- One Wire guardian receipt summary
- current provider smoke / loop-status output when available

## Compression Rule

Keep the common thread intact:

- the 13 named loops;
- the closure definition;
- Loop 1 trunk hypothesis;
- One Wire invariant;
- VSM/cybernetics frame;
- receipts before claims.

When context is tight, preserve evidence paths and exact blockers before preserving explanatory prose.

## Handoff Rule

A handoff packet must include:

- branch and dirty-state summary;
- changed files;
- verifier commands and outcomes;
- registration state;
- NATS/A2A status distinction;
- unresolved contradictions;
- next safe action.

## Forbidden Context Moves

- Do not turn demos into closure claims.
- Do not omit failed checks from summaries.
- Do not smooth over contradictions between runtime evidence and docs.
- Do not move One Wire quorum claims into archive fitness language unless the guardian receipt proves quorum.
