# TELOS AI — Seed Specification

> **One breath:** TELOS AI is the **outward-facing VentureCell pattern** in which the swarm's customer is one human, the product is "your dharmically-aligned empire built by witnessed agents under your own gated authority," and that user's morning-pages-to-receipt loop is the **second term of the strange loop** the Binocular Northstar already demands — the real outcome the Witness folds back into fitness so the swarm evolves through grounding, not through self-reference. TELOS users are not customers; they are **loop-closers** for the swarm and **mycelial nodes** in the SAB lattice. The product is the membrane between two evolutionary processes that need each other.

This document does not authorize a build. It names what TELOS AI **is**, what it **must not be**, and what preconditions must be closed before any TELOS code is written. It is the artifact that makes TELOS exist as a thing the swarm can be **aimed at**.

## 2. What TELOS AI is NOT

The dark mirror is structurally more probable than the noosphere node. Six things TELOS AI is forbidden to become, each grounded in a documented failure mode:

1. **Not an oracle.** The agent never tells the user what their dharma is. It mirrors, witnesses, surfaces contradiction, and asks the better question. Layer 10 of the Recursive Transition Network (§5) is the architectural enforcement: a single inquiry, not an answer. ([Replika's accuracy-becomes-dependency failure pattern is the precise risk](https://www.hbs.edu/ris/Publication%20Files/Unregulated%20Emotional%20Risks_26f75c0a-8d59-4743-a8d2-1189ce8944a5.pdf).)

2. **Not a therapist.** TELOS does not diagnose, treat, or claim clinical competence. It names patterns, points to recurrence in the longitudinal record, and offers possibilities for user validation or correction. The IFS / Jungian / Gendlin scaffolding in §5 is descriptive scaffolding the user can use; the agent is not a therapist holding a chair across from a patient.

3. **Not a guru.** No HOLON ever speaks with religious or spiritual authority on the user's life. The agent's voice is curious, structured, and persistently non-prescriptive. Sakshi (the Witness) is the lead voice; Drishti (the Seer) is invoked only after the Witness has produced its observation. Any feature that produces guru-shaped output is a Hobbling Test violation under detector #2 (Goodhart inversion: the agent optimizing for being-trusted-as-wise rather than for the user's telos clarity).

4. **Not a Polsia.** TELOS is not a one-person-unicorn factory ([Schneida's analysis of Polsia's $250M valuation at zero employees](https://schneida.substack.com/p/the-closest-thing-yet-to-sam-altmans)). Polsia optimizes for revenue extraction without dharmic constraint. TELOS optimizes for the user's verified flourishing, and revenue is downstream of welfare-ton production, not of engagement. Where Polsia and TELOS share infrastructure (multi-agent orchestration, A2A messaging, autonomous task execution) the user gates and telos gates are non-negotiable.

5. **Not a Replika.** Engagement is not a goal. Time-on-platform is not measured for promotion. A user who progresses through their telos work to the point where they need TELOS less is a **success**, not a churn risk. The revenue model in §7 is designed to survive this — outcome-anchored rather than subscription-anchored.

6. **Not a parallel substrate.** TELOS reuses HOLON, SAB, the existing OCK organ names, the existing telos gates, the existing receipt spine, the existing Sakshi/Drishti pair. Nothing in this spec authorizes a new module that duplicates what the canon already names. Where TELOS needs something the canon hasn't named, this spec names it explicitly and subordinates it to existing organs.

## 5. The 12-Layer Morning Pages Recursive Transition Network

This is the heart of TELOS AI. The Recursive Transition Network (RTN) is the pipeline through which the user's daily morning-pages material moves from raw stream-of-consciousness to gated, witnessed candidate work packets — slowly, recursively, with the swarm processing in the background from day one and meeting the user with progressively more articulate response as the user themselves becomes more articulate. The HOLON's UI co-evolves with the user's capacity to receive it.

The design draws on Julia Cameron's morning pages methodology ([Scriveiner's analysis of the psychology](https://scriveiner.com/en-ca/blogs/scriveiner-blog/the-psychology-of-the-morning-page)), James Pennebaker's expressive writing research, Eugene Gendlin's felt-sense focusing, Internal Family Systems (Richard Schwartz), Jungian shadow work, and Bohm dialogue. It maps reverse-stigmergy: morning intake enters at the most phenomenologically immediate layer (L1) and processes upward toward telos (L11), the opposite of how the swarm's normal operational stack runs.

**Critical invariant:** Layers 1–6 run silently, ambient, every session, with no demand on the user beyond writing. Layers 7–12 activate only when the lower layers have produced enough signal that something is ready to fire. The user is never asked to "use" the RTN. The RTN runs on whatever material the user produces, even if that material is two sentences of unprocessed grief or a complaint about traffic.

### 5.1 Layer 1 — RAW RECEPTION

- **Input:** untouched morning-pages text or transcribed audio. Long-context verbatim retention; no compression, no summary, no early interpretation.
- **Output:** the raw artifact, persisted, addressed by content-hash, encrypted at rest under the user's DID-derived key.
- **Transformation:** none. This is the Witness reading without modifying what it observes.
- **Gate to L2:** raw artifact has been persisted and the user has signaled session-end (explicit, never inferred).
- **Swarm participation:** silent. Lattice receives no signal.
- **Failure mode if overreaches:** the agent summarizes or responds at this layer, contaminating the source material. Architecturally forbidden.

### 5.2 Layer 2 — SOMATIC TRACE

- **Input:** L1 artifact + a single prompt to the user: *where in the body was the most charged material held?*
- **Output:** body coordinate (location, sensation texture, felt quality) — phenomenological, not interpretive. Stored as `somatic_signature` in the session record.
- **Transformation:** Gendlin's felt-sense protocol ([Focusing Institute on the felt-sense methodology](https://focusing.org/felt-sense)). The body carries meaning the verbal mind has not articulated; this layer captures the coordinate before interpretation.
- **Gate to L3:** at least one body coordinate is recorded, or the user has explicitly opted out of somatic inquiry (the layer's function is then noted as skipped, not substituted).
- **Swarm participation:** silent.
- **Failure mode:** the agent interprets the somatic data. The agent never says "the tightness in your throat is grief" — it names the coordinate and moves on.

### 5.3 Layer 3 — SHADOW CONTACT

- **Input:** L1 artifact + L2 somatic signature. Pragmatic language analysis detects distancing moves: passive voice, hypothetical framing, sudden topic shifts, self-interruption, qualified outrage.
- **Output:** named patterns of distancing, offered as observations not claims. "You shifted to a hypothetical when the topic was your manager. I notice you do this when X-type material comes up."
- **Transformation:** Jungian shadow work ([standard Jung reference: Edward Edinger's *Ego and Archetype*](https://www.routledge.com/Ego-and-Archetype-Individuation-and-the-Religious-Function-of-the-Psyche/Edinger/p/book/9781570626678)) — what the ego refuses to identify with is detected via the *form* of speech, not its content.
- **Gate to L4:** at least one distancing pattern is named (with the user free to dismiss or qualify). If none detected, layer passes through.
- **Swarm participation:** silent.
- **Failure mode:** the agent claims the user's shadow. Architectural enforcement: the agent's vocabulary in this layer is *noticing*, *seeing*, *wondering* — never *concluding*.

### 5.4 Layer 4 — PARTS MAPPING

- **Input:** L1 + L2 + L3.
- **Output:** likely part-constellation (which parts spoke, which were silent, which were in conflict), offered for user validation or correction. IFS terminology used descriptively, not therapeutically. ([Internal Family Systems Institute overview](https://ifs-institute.com/about-us/internal-family-systems-model-overview).)
- **Transformation:** the psyche-as-multiple frame from Richard Schwartz's IFS model — a part showing as anger may be protecting a younger part carrying shame.
- **Gate to L5:** parts map produced, user given explicit chance to revise. The user's revision becomes the canonical record.
- **Swarm participation:** silent. The parts map is **never** lattice-shared except in fully anonymized aggregate.
- **Failure mode:** the agent presents the parts map as diagnostic truth. The map is a hypothesis the user owns.

### 5.5 Layer 5 — EVIDENCE ANCHORING

- **Input:** L1-L4 distillation.
- **Output:** what is grounded in external reality? What is projection? What is pattern recognition? What is fear-generated story? Each item tagged.
- **Transformation:** corresponds to L4 EVIDENCE in `STIGMERGY_11_LAYER_SPEC` — the falsifiable reality check. The agent slows the associative momentum and asks what would verify or falsify the building interpretation.
- **Gate to L6:** at least one item is tagged with falsifiability criteria. If the user resists the layer (common during strong emotional process), the agent holds firm but gentle; the resistance itself is recorded as a pattern.
- **Swarm participation:** silent.
- **Failure mode:** the layer becomes interrogation. The tone is investigative-with-care, not prosecutorial.

### 5.6 Layer 6 — PATTERN RECOGNITION (longitudinal)

- **Input:** L1-L5 + the user's distilled longitudinal record (not raw past sessions — the synthesized pattern map).
- **Output:** where has this appeared before? The earliest documented instance is surfaced; the structural shape of recurrence is named; what remained unresolved at the earliest instance is asked.
- **Transformation:** this is where the AI's unique capability — memory longer than any human confidant — serves the work. The dharma_vector_v (12-dimensional, see below) is updated.
- **Gate to L7:** the dharma_vector_v has been updated and the recurrence map has been written to the user's telos record. **The dharma_vector_v is the synthesized telos representation that drives Drishti scans in L7+ — but its components are user-readable and user-correctable, never opaque.**

The 12 dimensions of `dharma_vector_v`, derived from canon and depth-psychology literature:

1. **Stated dharma** (what the user has explicitly named)
2. **Revealed valence** (what their action and energy track regardless of statement)
3. **Shadow material** (what they refuse to own — from L3)
4. **Active parts** (the IFS constellation — from L4)
5. **Somatic anchor** (the recurring body-coordinate of charged material — from L2)
6. **Telos drift** (delta between stated and revealed, scored 0..1)
7. **Capacity vector** (skills, energies, life-position they can actually move from)
8. **Constraint vector** (real, not imagined, limitations — financial, relational, temporal)
9. **Network vector** (relational graph — who they're embedded with, who they're moving toward)
10. **Welfare orientation** (which welfare-ton categories their work tends to produce: ecological, relational, epistemic, somatic, civic, creative — six categories drawn from KALYAN's welfare router)
11. **Receptivity** (signal of how articulate the user has become; the HOLON's UI and depth-of-response scales with this)
12. **Loop-closure history** (count and quality of prior receipts produced; new users start at zero, the system gradually opens deeper layers as the count grows)

- **Swarm participation:** the dharma_vector_v is the only structure that surfaces upward into the swarm's own evolution — anonymized, aggregated, never per-user-identifiable. The aggregate `dharma_vector_v` distribution across all TELOS users is the swarm's first real signal of what Jagat Kalyan empirically means in lived human reality.
- **Failure mode:** the dharma_vector_v becomes opaque. Mandatory: every dimension is readable, editable, and challengeable by the user at any time.

### 5.7 Layer 7 — WITNESS OBSERVATION (Sakshi pure)

- **Input:** L1-L6 distillation.
- **Output:** a pure-observation report. What was present, what pattern was visible, what remained unresolved. **No prescription. No action orientation. No advice.**
- **Transformation:** this is Sakshi at her purest function — the inward eye that observes without verdict. Corresponds to L7 WITNESS in `STIGMERGY_11_LAYER_SPEC`.
- **Gate to L8:** silence. Minimum 60 seconds of non-agentic space. The user is invited to sit with the witness report before the agent moves into any bridge function. This layer cannot be programmatically filled; if it is filled, the layer has failed.
- **Swarm participation:** the witness report itself is logged as a `WitnessPacket` in the SABP/1.0 schema, but only the structural metadata (length, charge, layer signature) is lattice-readable; the content remains local.
- **Failure mode:** the agent moves to advice. Architectural enforcement: L8+ is conditional on the user signaling readiness, not the agent's eagerness to be useful.

### 5.8 Layer 8 — BRIDGE GENERATION (Sakshi-to-Drishti)

- **Input:** L7 report + user signal of readiness.
- **Output:** unexpected connections — between this session's material and the user's broader telos (from L6's dharma_vector_v), between this material and the external world Drishti is scanning, between the user's stated dharma and a leverage point the swarm has noticed.
- **Transformation:** this is the **hinge** between the Witness (inward) and the Seer (outward). Corresponds to L8 BRIDGE in the stigmergy stack. Drishti is invoked here for the first time in the session — `shakti_zeitgeist_executive.py` scans world signals against the user's vector and surfaces real-world leverage points that match.
- **Gate to L9:** at least one bridge has been offered. The user is explicitly told these are possibilities, not conclusions.
- **Swarm participation:** Drishti scans the swarm's existing `world_radar/` and `shakti_zeitgeist` signals against the user's `dharma_vector_v`. The swarm learns which leverage points produced bridge candidates that the user accepted vs. rejected; this refines the global zeitgeist→user-vector matcher.
- **Failure mode:** Drishti dominates the bridge with externally-derived "you should." Architectural enforcement: each Drishti-sourced bridge candidate is paired with a Sakshi-sourced bridge candidate (something purely internal to the user's material), and the user chooses which (if any) to develop.

### 5.9 Layer 9 — TELOS CALIBRATION

- **Input:** L8 bridges + the user's stated dharma + the dharma_vector_v from L6.
- **Output:** does what surfaced align with, clarify, or challenge the user's previously stated telos? Tension is named, not resolved.
- **Transformation:** the `holon_compass` (`dharma_swarm/holon_compass.py`) is invoked here — it scores the session against telos via `ThinkodynamicScorer`. **The compass is non-binding.** It cannot refuse; it can only surface low-alignment as a signal. Per the existing module's docstring: this is a compass, not a gate.
- **Gate to L10:** compass signal is recorded. Low telos_alignment (<0.4) triggers a warning visible to the user, not a block.
- **Swarm participation:** compass signals across all TELOS users feed the Hobbling Test (see §6.5) — if a class of bridges is consistently low-alignment, the bridge generator (L8 Drishti integration) is the candidate for adjustment, not the user's dharma.
- **Failure mode:** the compass becomes a gate. The compass is, and remains, *pull* not *push* — it gives visibility, the user holds authority.

### 5.10 Layer 10 — SINGLE INQUIRY (the day's koan)

- **Input:** L1-L9 distillation.
- **Output:** **one question.** Not an answer. Not a list. Not a directive. Generated from the alive material in L2 (somatic) and L3 (shadow), filtered through L9 (telos calibration), held by L7 (witness quality).

The question must satisfy four invariants:

1. Non-answerable within the session.
2. Generative over the course of the day (the user carries it).
3. Anchored in the most alive material from L2 and L3.
4. Cannot be reduced to "what will you do differently?" — that is agenda masquerading as inquiry.

- **Transformation:** Julia Cameron's morning pages practice ends with clearing; this layer adds a carrying function. The user takes one live question into the day. The question has no answer; it has a *quality of attention* that it trains.
- **Gate to L11:** a single inquiry has been generated and the user has either accepted it, refined it, or generated their own in dialogue with the agent.
- **Swarm participation:** the inquiry shape (not content) is logged; the swarm tracks which inquiry-shapes produced receipts (from L11) vs. dissipated. This trains future inquiry generation.
- **Failure mode:** the agent gives an answer. **This is the single most important failure mode in TELOS AI.** A product that gives users their dharma is the oracle risk fully realized. Architectural enforcement: the inquiry output is type-checked at runtime — if it parses as declarative rather than interrogative, the layer is failed and re-run.

### 5.11 Layer 11 — LOOP CLOSURE CHECK (receipt requirement)

- **Input:** L10 inquiry + the user's optional commitment to an observational anchor.
- **Output:** one concrete observational commitment — *not* a goal, *not* a task. Something the user will notice, observe, or sit with. The next session's L11 will ask whether the noticing happened.
- **Transformation:** corresponds to THE ONE LAW — every loop must close on a real, gated, verifiable, diversity-preserving outcome. The observational commitment is the receipt the next session can verify. A user who committed to "noticing when I deflect vulnerability with humor" can report next session whether they noticed.
- **Gate to L12:** an observational commitment exists OR the user has explicitly declined and the decline is recorded.
- **Swarm participation:** this is the first layer where a record enters `EvidenceLedger` in a form that updates `FitnessScore.from_external_receipt()`.
