## 1. Purpose

This plan collapses the original Wayfinder destination, the admitted HELM leg-one
work, the Nihonga interaction findings, the reverse-spec evidence, and the observed
2026-09-01 runtime into one challengeable build target.

It does not promote a session transcript, prototype, model opinion, or this plan into
repository canon. Canon and owner records win on conflict. It also does not redefine
`fully wired` to mean `production alive`.

## 2. Product sentence

**One quiet, recursively deep HELM lets the operator converse with, inspect, route,
and verify the whole swarm from one persistent seat, while every displayed claim and
available action retains its real owner, freshness, evidence, and authority.**

There is one visible product. tmux, Git worktrees, provider CLIs, Python services,
Treehouse, and future renderer processes are plumbing or bounded tools, never rival
operator seats.

## 3. Binding interpretation for this prototype

The current experiential oracle is the admitted Bun/React/Ink application with the
Python `terminal_bridge` owner gateway. It remains the prototype chassis until a
replacement proves behavioral parity and a measured improvement.

The destination architecture is:

```text
operator input / terminal cells
            |
            v
future Rust terminal kernel  <->  Bun semantic state + reducer
                                      |
                                      v
                              Python owner gateway
                                      |
                    canonical state owners / providers / evidence
```

Rust is a destination, not a present-tense claim. No second visible TUI or dual
renderer is admitted. The Rust kernel may replace Ink only after parity, latency,
resize, recovery, and accessibility evidence clears the Ink oracle.

## 4. Authority and modality contract

These states are deliberately non-substitutable:

```text
configured != requested != served != observed
observed   != completed != verified != fresh
verified   != authorized != effected
```

Model prose is narration with authority `NONE`. It cannot promote claims, authorize
effects, or turn a configured route into a verified-on-call seat. Only canonical
owners/evaluators can promote state.

The provider boundary must preserve this invariant:

```text
ObservedRouteReceipt != VerifiedOnCall != EffectAuthority
```

Client-supplied prompt bytes remain user-role data. They may bind a request but must
not be copied into a higher-authority system context. A useful typed handoff is:

```text
OwnedContext<Owner, SourceEpoch, Route, PromptDigest, OneUse>
```

The bridge may issue that context once to the matching fresh provider turn. A client
cannot forge it, replay it, or retarget it to another route. Repository and runtime
material inside the context is read-only evidence, not effect authority.

Only explicitly allowlisted structural owner projections may cross an external
provider boundary. Free-form session memory and working memory remain local until a
typed owner supplies secret screening and provenance; secret-like values in admitted
projections fail closed to a redaction marker and the receipt records that disposition.

The execution boundary and its later outcome are separate facts:

```text
ContextReceipt<BoundaryAt, OutcomeAt, Route, Digest,
               Disposition, LaneOutcome, Authority=NONE>
```

The boundary is durably staged before provider execution. Until provider-start
evidence exists, an offered context remains `offered_unconfirmed`; a bridge restart
may close it only as `interrupted`, never retrospectively as attached or completed.

## 5. The experience to prove

One uninterrupted local journey must demonstrate:

1. Quiet boot into the HELM with exact checkout, commit, dirty state, bridge state,
   route request, effect posture, and honest `N/7`, `?/7`, or `UNAVAILABLE` state.
2. The same state expands into the responsive Whole HELM: Home, Conversation,
   Activity, Evidence, and System. Layout changes do not create another product.
3. A fresh conversational turn receives server-owned HELM/Wayfinder/repository
   context and returns narration only, with tools disabled.
4. Precise operator language and slash commands steer local panes/routes through the
   actual reducer. Ambiguous conversational language still reaches chat byte-for-byte.
5. Status, repository, runtime, sessions, routes, and evidence end at a canonical
   local owner or an explicit `UNAVAILABLE`/`UNKNOWN` result—never static success copy.
6. Requested, served, and verified model identity remain visibly separate. Route
   switching is recorded; it does not imply a fresh completion receipt.
7. Cancellation closes the active lifecycle honestly. Restart restores durable
   conversation/session evidence without inventing continuity.
8. Activity and evidence show the causal braid from operator intent through
   bootstrap, route, provider, completion/failure, and durable session record.
9. The closeout is quiet and exact: what changed, what is held, what diverged, and
   what remains unproved.

An external provider success is useful evidence but is not required for a truthful
local pass. When credentials or an exact model route are absent, typed
`UNAVAILABLE` is the correct working outcome.

## 6. Meaning of “working prototype”

The prototype is locally working when every control exercised in the journey crosses
its real local seams and terminates in one of:

- a canonical owner projection;
- a real provider/session receipt;
- an explicit `UNAVAILABLE`, `UNKNOWN`, `STALE`, or `HELD` state; or
- a visibly typed `SIM` fixture used only by a disposable test journey.

This is not the production ship claim. Production `alive` still requires the
leg-one truth contract, including a recently verified seven-seat bench, performance
and soak evidence, operational health/rollback proof, and all governance gates.

## 7. Bounded Treehouse role

Kun Chen's Treehouse pattern is useful only for disposable, parallel experiments.
It is not the HELM integrator or a source of Git authority.

Any future use must carry a receipt shaped like:

```text
Lease<Path, Holder, CommonDir, BaseCommit, ReturnCondition>
```

The current installed pool does not carry enough of that type: it shares the remote
name while using another Git object database that cannot see the admitted HELM head.
No pool expansion, branch integration, or reset/return operation belongs in this
prototype convergence lane.

## 8. Explicit exclusions

- No Textual or legacy TUI revival.
- No dashboard or web control surface presented as HELM.
- No wholesale Operator Seat, reverse-spec, Nihonga, stash, or custody-branch merge.
- No static peer tabs, decorative liveness, aggregate health score, or key-presence
  claim presented as a live model.
- No model consensus presented as proof.
- No post-hoc approval or broad effectful hand.
- No renderer rewrite before the current journey is an executable comparison oracle.
- No fixture or rehearsal data entering live verification or authorization paths.

## 9. Convergence slices

| Slice | Outcome | Proof |
|---|---|---|
| A | Lawful worktree boots the real Python bridge | process tree + compact PTY smoke |
| B | Server-owned HELM context reaches fresh chat | forged/replay tests + real turn |
| C | Existing local-language steering reaches the reducer | App boundary tests + live journey |
| D | One managed launcher and durable receipt | exact socket/session/process evidence |
| E | Full local journey and restart recovery | captured causal/evidence sequence |
| F | Missing owner projections become real or typed unavailable | owner contract tests |
| G | Seven-seat live proof, performance, soak, health, rollback | production admission gates |
| H | Rust kernel parity experiment | oracle diff + measured improvement |

Slices A–E form the experiential prototype. Slices F–H remain follow-on production
and architecture work; they must not be collapsed into a premature success label.
