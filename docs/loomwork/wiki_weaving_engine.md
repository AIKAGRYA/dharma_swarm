# Wiki Weaving Engine — dharma_swarm × Karpathy Wiki

**Locked:** 2026-05-07
**Status:** v0 implementable spec. Path-precise. 14-day ship gate.
**Frame:** dharma_swarm becomes the **loom** that ingests scraped sources, atomizes records into Karpathy-style atoms, weaves cross-pollinations, and surfaces revelations the world can read. The wiki at `~/.dharma/knowledge/wiki/` is the substrate; the loom turns it into a public-facing dot-connection organ.

**Wiki current state (verified 2026-05-07):** `~/.dharma/knowledge/wiki/` holds ~300 `.md` files across `concepts/`, `connections/`, `qa/`, `mocs/`, `research/`, `_meta/`. CLI at `~/bin/wiki` exposes `list / show / search / fzf / related / backlinks / graph / random / stats / index / log / edit / path / open`. Index is regenerated by `regen_wiki_index.py`. Atoms today are mostly internal (contemplative-bridges, llm-cognition, self-evolution MOCs). The loom *adds* a world-facing `concepts/world/` namespace WITHOUT touching the existing internal tree.

## SECTION 1 — The Weaving Loop (orchestration architecture)

Eight stages, each mapped to existing dharma_swarm capability + new wiki_loom module + provider tier + cadence + cost.

| # | Stage | Capability reused | New module | Provider tier | Cadence | Per-call cost |
|---|---|---|---|---|---|---|
| 1 | **Scout** — poll feed, fetch new records, normalize to raw artifact | `agent_runner.RoutedCompletionProvider`; `browser_agent.py` for HTML; existing `auto_research/` for arXiv-style sources | `wiki_loom/scout.py` (base + per-source subclasses) | T0 (no LLM — HTTP/RSS/API only) for fetch; T1 (Ollama Cloud GLM-5) for HTML→text where needed | per source: real-time (PubMed, GFW alerts, EDGAR), 15-min (court filings, regulatory dockets), hourly (news), daily (academic) | $0 fetch / ~$0 GLM-5 |
| 2 | **Atomize** — convert raw record to wiki atom per `_meta/wiki_atom_schema.md` | `insight_brief.py` (forced-citation pattern); `auditor.py` (claim extraction) | `wiki_loom/atomizer.py` | T1 (Ollama Cloud GLM-5 / DeepSeek-v3.2) primary; T2 (Claude Haiku) fallback for ambiguous records | per-record on arrival, queue depth max 500 | ~$0 GLM-5 / $0.0002 Haiku |
| 3 | **Link** — for each new atom, scan existing wiki for candidate connections; propose edges with confidence | `catalytic_graph.py` (graph primitives); `concept_blast_radius.py` (semantic neighborhoods); `wiki backlinks` CLI | `wiki_loom/linker.py` | T0 embedding (local nomic-embed via Ollama, free); T1 GLM-5 for ranking & rationale | per atom on creation | ~$0 |
| 4 | **Pattern** — sweep atom graph, identify dot patterns (≥3 atoms across ≥2 source classes corroborating same operative claim) | `cascade.py` (strange-loop iteration GENERATE→TEST→SCORE→GATE); `claim_graph.py`; `catalytic_graph.py` Tarjan SCC | `wiki_loom/pattern.py` | T1 GLM-5 for clustering hypotheses; T2 Haiku for narrative synthesis | every 6 hours | ~$0.50/sweep |
| 5 | **Revelation promote** — when pattern crosses confidence + corroboration thresholds, promote to revelation, generate human-readable narrative + cited source list, queue for review | `quality_forge.py` (multi-pipeline scoring elegance/behavioral/dharmic); `insight_brief.py` (forced citation infrastructure); `citation_index.py` | `wiki_loom/revelation.py` | T2 Claude Haiku primary; T3 Sonnet for revelations flagged HIGH-IMPACT | on threshold cross | $0.05–$0.50/revelation |
| 6 | **Witness gate** — every promotion passes telos gates: no vulnerable-person exposure, no libel risk, no hallucinated citation, no operationally-dangerous detail | `witness.WitnessAuditor` (existing class with `AuditFinding`); `anekanta_gate.py`; `pramana` provenance tagging | `wiki_loom/gates.py` (extends `WitnessAuditor` with wiki-loom-specific finding types) | T2 Haiku for routine; T3 Sonnet for edge cases | sync (blocking) before publish | $0.01–$0.10/check |
| 7 | **Publish** — render approved revelation to public wiki (separate `concepts/world/` tree), commit + push to GitHub Pages site, generate RSS, generate digest tweet/post | static-site generator (Hugo or `mkdocs-material`); `~/bin/wiki publish` (new subcommand); existing `audit_queries.py` for change-tracking | `wiki_loom/publisher.py` + `wiki publish` CLI command | T0 (no LLM — pure render+git push) | sync after gate pass | $0 |
| 8 | **Algedonic feedback** — external readers flag inaccuracies via web form / GitHub issue; algedonic loop reroutes to retraction/correction queue; pattern-detector learns | `scripts/algedonic_triage.py` (already launchd-deployed, 6 functions); `algedonic_bridge.py`; `algedonic_activation.py` | `wiki_loom/feedback.py` (adapter from web form / GH issues into algedonic_triage queue) | T1 GLM-5 for classification; T2 Haiku for retraction-narrative generation | real-time on inbound | ~$0/flag |

**Cadence orchestration** — add `run_wiki_loom_loop()` to `orchestrate_live.py` as a 9th concurrent loop alongside swarm/pulse/evolution/living-layers/health/zeitgeist/witness/training. Tick = 60s; per-tick it pumps the scout queue, drains atomizer/linker queues, fires pattern sweep on schedule, processes revelation queue, blocks on witness gate, pushes publisher.

**Provider routing rule** — every loop stage uses `RoutedCompletionProvider` with `allow_provider_routing=True` and `preferred_provider_hint=ProviderType.OLLAMA_CLOUD_FREE` first. Falls back to OPENROUTER_FREE → CLAUDE_CODE → CLAUDE_API only on explicit need (revelation narrative, witness edge cases, retraction prose). Free-models-first instinct (`feedback_free_models_first`) governs.
